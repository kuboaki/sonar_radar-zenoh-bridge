# バグ報告: hakoniwa-pdu 1.6.2 — フィールドを持たないメッセージ型の生成コードが `IndentationError` になる

対象: https://github.com/hakoniwalab/hakoniwa-pdu-python

提出済みIssue: https://github.com/hakoniwalab/hakoniwa-pdu-python/issues/50 (2026-08-03)

## 概要

`hakoniwa-pdu==1.6.2` に含まれる、フィールドを1つも持たないROSメッセージ型(例: `std_msgs/Empty`)の生成済みPythonコード(`pdu_pytype_Empty.py`)が構文エラー(`IndentationError`)になり、importできない。

## 再現手順

```bash
pip install hakoniwa-pdu==1.6.2
python3 -c "from hakoniwa_pdu.pdu_msgs.std_msgs.pdu_pytype_Empty import Empty"
```

## 実際の結果

```
Traceback (most recent call last):
  File "<string>", line 1, in <module>
  File ".../hakoniwa_pdu/pdu_msgs/std_msgs/pdu_pytype_Empty.py", line 16
    def __str__(self):
    ^^^
IndentationError: expected an indented block after function definition on line 14
```

## 原因(推測)

`pdu_pytype_Empty.py`(`hakoniwa-ros2pdu`による生成コード、コメントに`"Generated by hakoniwa-ros2pdu."`と記載あり)を確認すると、`__init__`メソッドの本体が空になっている。

```python
class Empty:
    """
    ROS message: std_msgs/Empty
    Generated by hakoniwa-ros2pdu.
    """


    def __init__(self):

    def __str__(self):
        ...
```

フィールドを持つメッセージ型(`std_msgs/String`, `std_msgs/Bool`など)では、`__init__`の本体に各フィールドの初期化コード(`self.data = ""`等)が生成されるため問題ないが、フィールド数が0の場合、コード生成器が本体に何も出力しない(`pass`すら出力しない)ため、空のブロックとなり構文エラーになると推測される。

## 期待される動作

フィールドを持たないメッセージ型でも、`__init__`の本体に少なくとも`pass`が生成され、正しくimportできること。

## 影響範囲(調査済み)

手元の`hakoniwa_pdu/pdu_msgs`配下(`std_msgs`/`sensor_msgs`/`geometry_msgs`/`hako_msgs`等)を機械的に走査したところ、この問題が再現するのはフィールド数0の`std_msgs/Empty`のみだった(他の型はいずれか1つ以上フィールドを持つため影響なし)。ただし、他の未確認パッケージにフィールド数0の型が存在すれば同様の問題が起きると考えられる。

## 環境

- `hakoniwa-pdu` 1.6.2 (PyPI)
- Python 3.12
- macOS (arm64)
